# 家庭识别凭据与配额：家庭自带 key 加密存储、不回退，实例配额按自然月统计

截图识别有两种来源。实例用自己的服务商给每个家庭一份相同的**识别配额**（`STOCKUP_RECOGNITION_MONTHLY_QUOTA`），为 0 表示实例不提供识别；家庭管理员也可以给家庭配置自己的服务商、API key、可选的 base URL 和模型，即**家庭识别凭据**，每个家庭至多一份，全家共用、不计配额。家庭有凭据时一律用它；凭据调用失败（认证失败、余额不足、服务商不可达等）时识别以 `household_key_unavailable` 失败，**不回退**到实例的服务商：悄悄改用实例配额会让管理员发现不了自己的 key 已经失效，也会让实例主人替这个家庭买单。服务商答非所问（结构化输出解析失败等）不是 key 的问题，仍按普通的识别失败处理。保存凭据前先用这组配置带一张小图实际调用一次服务商（限制输出 token），不通过则拒绝保存并只返回原因类别（认证失败、模型不存在、无法连接、地址不是公网、其他服务商错误，读不了图的模型归入最后一类），服务商的原话只记进服务端日志，所以填错的 key 或不支持图片的模型在保存时就暴露。

开放注册时任何人都能当上家庭管理员，家庭填的 base URL 就是让服务器替他发请求的地址，所以只接受 https，且每次请求前（保存时的校验和每次识别）都解析主机名，任一地址落在回环、私有、链路本地（含 169.254.169.254 云元数据）、CGNAT、未指定等非公网网段就拒绝，也不跟随重定向；实例自己的配置来自运维，不受此限。解析与连接之间仍有 DNS 重绑定的窗口：检查用的地址并未钉住给实际连接使用。

key 用 `STOCKUP_ENCRYPTION_KEY`（32 字节随机数的 base64，格式不对则启动失败）做 AES-256-GCM 认证加密后存库，家庭 ID 作为附加认证数据，密文被挪到别的家庭的行上无法解开。库里只额外保留末四位明文，供界面显示掩码；接口从不返回 key 本身，家庭管理员只能看到服务商、base URL、模型和末四位，只能替换或删除，普通成员什么都看不到。没配加密密钥时整个功能关闭：设置页不显示这一项，相关接口返回 `household_credentials_unavailable`，已存的凭据不再读取，家庭改用实例配额——这时家庭管理员已经无法管理凭据，按功能关闭处理，而不是让家庭卡在一份无法修改的配置上。加密密钥换了或丢了，已存的 key 就解不开：识别直接以 `household_key_unavailable` 失败，状态显示不可用，家庭管理员重新填一次 key 即可，不回退。

配额按家庭、按自然月计算，月份以实例时区为准，每月 1 日恢复；直接从 `recognition` 表统计本月由实例服务商处理、成功并生成了识别草稿（结果里至少一条商品）或仍在识别中的记录，不另建用量表；草稿之后被确认或删除不影响计数。识别中的记录也占一次，这样同时上传的几张截图不会一起越过配额的最后一次；识别失败（含服务重启中断）或截图上一条商品也没识别出来则把这一次还回去，服务商出错或截图看不清时成员不白白浪费次数。判断配额与新建识别记录在同一个事务里、先锁住家庭行，并发上传逐个占用剩余次数。为区分来源，每条识别记录记下它用的是家庭凭据还是实例服务商，用家庭凭据的识别不计入配额。

## Considered Options

- 家庭 key 失败时回退到实例 key（被否：失效的 key 不会被发现，实例主人也会在不知情时替这个家庭付费）
- 明文或可逆编码存 key（被否：数据库备份或误泄露即等于泄露所有家庭的 key）
- 没配加密密钥时也允许保存 key（被否：只能明文保存）
- 新建用量表、识别成功时累加（被否：与 `recognition` 表重复，还要处理两者不一致；直接统计已有记录就够）
- 只统计成功的识别、不算识别中的（被否：同时上传多张时每张都看到还有余量，会一起越过配额）
- 按滚动 30 天或按 token / 费用计量（被否：规则难懂；自然月在下月 1 日恢复最直观）

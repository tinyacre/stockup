# 开放注册需显式打开，并以邮箱验证码创建账号和家庭

实例默认不开放注册：只有运维设置 `STOCKUP_SIGNUP=open` 后，访客才能自己注册，避免公网实例在运维不知情时对所有人开放。开放注册必须同时配置 SMTP，否则启动失败，因为验证码邮件是证明新账号邮箱真实可用的唯一手段。注册是一次请求：访客先收到 6 位验证码，再连同用户名、显示名和密码提交；服务端在同一个事务里消费验证码、创建账号和一个名为「<用户名> 的家」的家庭，注册者成为家庭管理员、不成为实例管理员，然后直接登录。数据库里因此不存在未验证邮箱的账号，也不需要清理半途放弃的注册。

验证码规则沿用 fangcun：10 分钟有效、每个码最多试 5 次、同一邮箱同一用途 60 秒内只发一次、任意一小时内最多 5 次（滑动窗口）、新码替换旧码，库里只存以服务端密钥为 key 的 HMAC。发码接口对已注册和未注册的邮箱一律返回 204，已注册的邮箱同样计入限流但不发信，邮件在响应之后异步发送，所以响应内容和耗时都不暴露邮箱是否注册过；代价是用已注册邮箱注册时只会得到「验证码错误」，而不是「邮箱已被使用」。

SMTP 和 Cloudflare Turnstile 都是可选能力：一组环境变量全不配即关闭，只配一部分则启动失败并列出所缺变量。没有 SMTP 时一切保持原样（只能由实例管理员建家庭、由家庭邀请加入）。配置 Turnstile 后，注册、发验证码、登录（含 MCP 授权登录）、找回密码和邀请加入都要先过人机验证；Web 登录与 MCP 授权登录共用同一个登录接口，不设免验证的入口，因为任何例外都会成为脚本绕过的路径。

## Considered Options

- 先创建账号、再发验证链接确认邮箱（被否：库里会出现未验证的账号，需要额外的状态和清理；链接还要求邮件里的地址与实例对外地址一致）
- 使用 Better Auth 的 email OTP 插件（被否：它自行建账号，无法与创建家庭放在同一个事务里，也不提供按邮箱的滑动窗口限流）
- 注册后等实例管理员审批（被否：家庭自助使用的场景里，没有人愿意承担审批）
- 只要配置了 SMTP 就自动开放注册（被否：配 SMTP 常常只是为了找回密码，不应顺带向所有人开放）
